## What this is

Léna Gaubert's personal Jekyll site (kittog.github.io), built on the `jekyll-whiteglass` theme gem. It hosts a blog (at `/blog/`), research/CV/teachings pages, and course materials (assets/cours). The homepage (`index.md`) is a static al-folio-style profile page (photo floated right, text wraps around it), not the blog index. There is essentially no application code here — content lives in Markdown/YAML front matter, and layout/styling comes from the theme gem installed outside the repo (not vendored in `_layouts`, which is empty on purpose).

## Commands

```bash
bundle install                                    # install gems (Jekyll ~> 4.1, jekyll-whiteglass)
bundle exec jekyll serve                          # local dev server with live reload (default: http://localhost:4000)
bundle exec jekyll build                          # build to ./_site
JEKYLL_ENV=production bundle exec jekyll build --baseurl "/kittog.github.io"  # mirrors the CI build in .github/workflows/main.yml
```

There are no tests, linters, or a JS/CSS build step in this repo.

## Deployment

Pushing to the `source` branch triggers `.github/workflows/main.yml`, which builds with Jekyll and deploys to GitHub Pages. There is no manual deploy step — do not hand-build and push `_site`.

## Architecture / content model

- **Theme override pattern**: to change a layout or include, copy the corresponding file out of the `jekyll-whiteglass` gem (installed at the path shown by `bundle show jekyll-whiteglass`) into this repo's `_layouts/`/`_includes/`, per [Jekyll's theme override docs](https://jekyllrb.com/docs/themes/#overriding-theme-defaults). Don't edit the gem in place. `_includes/head_custom.html` is the theme's designated (intentionally empty) hook for site-specific `<head>` additions — currently used for the homepage's floated-profile-picture CSS.
- **Site-wide settings** (title, author, profile info, plugins, permalink structure, kramdown options) live in `_config.yml`. `baseurl`/`url` are tied to this GitHub Pages repo — changing them affects the production build.
- **Top-level nav** is data-driven from `_data/navigation.yml`, independent of which `.md` pages actually exist — adding a page does not add it to the nav, and vice versa.
- **Translatable UI strings** (date formats, "read more", archive labels, etc.) live in `_data/i18n.yml`, keyed by locale.
- **Standalone pages** (`cv.md`, `research.md`, `teachings.md`, `archive.md`, `404.md`) are plain Markdown with YAML front matter (`layout`, `title`, `permalink`) — no logic, just content plus whatever the chosen theme layout renders around it. `index.md` (the homepage) and `blog/index.html` (the blog listing) are special-cased — see below.
- **Blog is at `/blog/`, not the homepage**: `blog/index.html` must stay a literal `index.html` file (not `.md`) with `layout: home`, because the legacy `jekyll-paginate` plugin only recognizes a page whose *source filename* is exactly `index.html` as its pagination template. `paginate_path` in `_config.yml` is scoped under `/blog/page/:num/` accordingly. The site root (`index.md`) is unrelated to pagination — it's a static profile page.
- **Blog posts** live in `_posts/`, named `YYYY-MM-DD-title.md`, front matter `title`/`layout: post`/`tags`. `excerpt_separator` is `<!-- more -->`.
- **Archives/categories/tags** are generated by the `jekyll-archives` plugin per the permalink patterns in `_config.yml` (`/categories/:name/`, `/tags/:name/`); pagination (blog listing only) is via `jekyll-paginate` (5 posts/page).
- **Course materials** (`assets/cours/`) are static PDFs/scripts/notebooks explicitly whitelisted via `include:` in `_config.yml` (Jekyll excludes underscore-prefixed and dotfiles by default, so this override is required for them to be copied into `_site`).
